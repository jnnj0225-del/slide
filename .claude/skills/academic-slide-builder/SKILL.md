# 学会スライド作成スキル

論文原稿・解析結果・過去スライドから、学会発表用の .pptx(口演/ポスター)を作る。
医学系学会(臨床研究・後ろ向きコホート・生存解析が中心)を想定する。

## 基本原則

1. **数値を創作しない。** スライド上の数値・図表はすべて、ユーザーが渡した原稿・解析結果に由来させる。原稿に無い数値は空欄(`[要確認]`)にして質問する。
2. **原稿と図表の不一致は黙って直さず報告する。** 例: 本文の症例数と図の n が違う、HR や CI が表と図で違う。
3. **1スライド1メッセージ。** 結果スライドのタイトルは「項目名」ではなく「結論の一文」にする。
4. **確認が必要な項目は推測で埋めない。** COI、倫理審査番号、共同演者、学会指定の様式・サイズ・時間は、原稿か本人から得る。
5. **患者情報を載せない。** 氏名、ID、生年月日、撮影日が写った画像は使わない。画像・術中写真に個人が特定される情報が無いか確認する。

## ワークフロー

### Step 1: 条件の確認(不足分だけ聞く)

すでに会話や添付から分かるものは聞かない。聞くのは次の点のみ。

- 学会名・セッション種別(口演/ミニオーラル/ポスター)
- 持ち時間(発表+質疑)、またはポスターの指定サイズ(縦横・向き)
- 言語(日本語/英語)
- 発表者情報: `references/presenter.md` を読み、不足を確認する
- 共同演者・COI・倫理審査情報(原稿にあればそこから取る)

### Step 2: 材料の読み込み

- アップロードされたファイルは `/mnt/user-data/uploads/` にある。形式ごとの読み方は file-reading スキルに従う。
- 過去スライド(.pptx)は `markitdown` で内容を、サムネイル(pptxスキルの `scripts/thumbnail.py`)で見た目を把握する。**配色・フォント・レイアウトの癖を抽出**し、新しいスライドに引き継ぐ。ユーザーが「テンプレとして使う」と言った場合は、pptxスキルの編集手順(unzip→XML編集)でそのファイルをベースにする。
- 論文原稿からは、目的、対象・方法、主要評価項目、結果の主要数値、結論、限界を抜き出し、一覧にして手元に置く(後のチェックで使う)。
- 解析結果の図表(画像)は、中身を目視で確認する。軸ラベル、単位、リスク数表(at-risk)、CI の有無を見る。

### Step 3: 構成案をユーザーに提示して承認を得る

スライドを作る前に、必ず構成案を出す。形式は表: `# / タイトル(結論文) / 載せる内容 / 使う図表 / 想定秒数`。

- 口演: `references/slide-structure.md` の枚数・時間配分に従う
- ポスター: `references/poster-guide.md` に従う
- 構成案の最後に、**不足情報・原稿間の不一致**を箇条書きで添える

承認(または修正指示)が出てから Step 4 に進む。

### Step 4: スライド生成

1. **先に** `/mnt/skills/public/pptx/SKILL.md` を読む(作成手順、pptxgenjs の注意点、検証スクリプトがある)。
2. デザイン方針: **まず `references/house-style.md` を読み、`scripts/nu_style.py` を使って作る**(フォント・配色・中央揃え・ロゴ配置はこちらが優先)。以下は一般的な目安:
   - 16:9(口演。学会指定が4:3ならそれに従う)
   - フォントはメイリオ(house-style)。会場PCで崩れにくい標準フォントのみ使う
   - 本文 20pt 以上、スライドタイトル 40pt 以上(house-style)。小さくなりすぎるなら内容を削る
   - 配色は2〜3色。過去スライドがあればその配色を優先
   - 図表は余白を確保して大きく置く。表は全部載せず、主要行だけ載せる(全体は付録へ)
   - 1スライドの文章は3〜5行まで
3. 必須スライド(口演): 表紙、COI開示、(倫理審査の記載はMethods内または専用)、背景、目的、方法、結果(複数)、考察、限界、結論、謝辞(任意)、付録(バックアップ)
4. スピーカーノートに、そのスライドの発表原稿(目安: 日本語で1分あたり約300〜350字)と秒数を入れる。
5. 付録スライドに、想定質問に備える補足図表(サブグループ、多変量解析の全表、感度分析など)を置く。ただし、データが原稿・解析結果にある場合のみ。

### Step 5: 品質チェック(必須)

1. **画像化して目視確認**する(pptxスキルの手順に従い、LibreOffice等でPDF→画像化)。文字のはみ出し、重なり、図の欠け、フォントの崩れを探して直す。
2. `scripts/office/validate.py`(pptxスキル)で .pptx を検証する。
3. `references/stats-checklist.md` の統計記載チェックを全スライドに適用する。
4. `references/conference-etiquette.md` の学会作法チェックを適用する。
5. スライド上の数値を Step 2 の一覧と突き合わせる。

チェック結果は、成果物と一緒に簡潔に報告する(合格項目は省略し、**要確認・修正した点だけ**を書く)。

### Step 6: 想定問答

`references/qa-guide.md` に従い、想定質問と回答案を作る。出力は Word(.docx、docxスキルに従う)を既定とし、質問が10個以内の短いものはチャット内に書いてもよい。

## 出力物

- `<演題略称>_口演.pptx` または `<演題略称>_ポスター.pptx`(スピーカーノート入り)
- `<演題略称>_想定問答.docx`(依頼があった場合、または口演の場合の既定)
- 完成したら present_files で渡し、要確認事項を最後に短くまとめる

## 修正依頼への対応

「ここだけ直して」「時間を5分に短縮して」といった依頼では、全体を作り直さず、既存の .pptx を編集する。時間短縮では、削るスライドの候補を先に提案し、付録へ移すことを基本にする。
